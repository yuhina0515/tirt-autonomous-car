# 官方圖面重建、物理模擬與 squad 修正

## 結果與範圍

已建立可執行的完整圖面路線草稿、受限制的2.5D世界、獨立軌跡裁判與離線回放，並修正一個已重現的原生控制錯誤。**尚未達成五次連續完成，也未核實為官方完整度量賽道。** 上方迴路及下方TAIWAN均有建模；原圖無法確認的方向、橋接、比例、高度與F用途仍為明示假設。不能把這份草稿或軟體測試通過等同於正式賽道／實車驗收。

主來源為使用者確認的[11/7指定組官方頁](https://www.tirtpointsrace.org/Registration/Event/ba032d0d-103c-4902-9559-b58fc8772b8b)。沿用已保存、雜湊核對一致的中文PDF；第5頁原始內嵌地圖為1240×1201 pixels，較整頁PNG清楚。三位獨立審查者皆使用目前模型，分別檢查圖面／拓撲、物理與控制／驗收；由主代理統一修改。

## 建置內容

`simulation/reconstructed_course.json`保存211個原圖像素頂點、209個有向路線門、T／I支路、A內支線、急彎例外與機構。依假設比例換算路線長67.187m；**這個長度、0.19m道路寬及分層高度均不是官方實測尺寸**。分層保持重複XY的路段身分，不把俯視交叉直接合併成可走捷徑。官方來源契約`official_course.json`仍保留未核實欄位，不因可執行草稿而自動填成已證實。

`tools/course_world.py`負責分層支撐、局部坡度、前伸感測器、假設前輔助輪造成的車身俯仰、馬達死區／遲滯／滑行、電量與輪差，以及摩擦受限的轉向。感測器只讀取所在可見表面的白線，不透過橋面看到下層。非行駛支線也有實體路面與白漆，可造成實際觀測歧義。升降台需確認兩輪都停止才開始下降；蹺蹺板使用車重力矩、慣量、阻尼與角度止擋。

這是接觸式2.5D近似，並非完整剛體引擎：沒有完整滾轉、懸吊、騰空／落地、側滑、前輔助輪失去接觸後的翻倒、輪胎／齒輪箱靜摩擦或量測過的扭力曲線。現有前輔助輪位置及感測高度是假設，不能作為真車爬坡能力的證明。模型對縱向與橫向抓地分別限幅，也沒有完整摩擦橢圓耦合。

`tools/run_course.py`將實際INO／controller.h編譯成主機介接，控制器只收到ADC與時間；沒有讀取真實位置、關卡答案或路線門。五個不同種子、每次物理參數及來源／模型雜湊在執行前寫入manifest。每次保留5ms軌跡、原生來源、模型與賽道快照，拒絕覆寫既有批次。

`tools/course_referee.py`從軌跡重算車體涵蓋白線、驅動輪完整接地範圍、分層／有向門、反向移動、機構及終點越線；車體與車輪在記錄間以不超過1mm／0.01rad再取樣檢查。這是有限解析度檢查，並非解析式連續碰撞證明。裁判核對位移、輪速、高度與俯仰的物理一致性，並以宣告種子重新產生感測雜訊、取樣及延遲，接著重播真正的控制核心。`lapDone`或手填一串成功布林值都不足以通過。

`tools/audit_course_run.py`核驗既存manifest、模型、賽道、程式與軌跡雜湊；可使用凍結版或另存版本的較嚴格裁判重審舊紀錄。`simulation/course_replay.html`產生不需伺服器的HTML，能切換試驗、播放、拖曳及比對原圖／推定路線／實際軌跡與高度。

## 已確認與修正的問題

- **原生搜尋的掉線計時未清除**：`F8→F0→F8→F0`等短暫掉線序列會沿用第一次掉線時間。原本125ms就進入Gap；修正後125、184ms仍維持Search，185ms才達到新一段連續60ms掉線。重複回線不能延長絕對800ms搜尋期限。主韌體僅採用這項已重現修正；速度、感測器角色、升降23.35秒及180秒上限維持。
- **幾何重複頂點除以零**：平面輔助函式忽略零長線段，完全退化路徑明確拒絕。
- **開發中模型接縫**：修正坡道高度只在頂點計算、重疊區低淨空、蹺蹺板端點、升降後無接收路面與遺漏支線。分析高度與儲存頂點也已一致。中心線25mm取樣沒有發現非機構區淨空衝突；獨立審查另外取樣車體範圍未發現此類衝突。這些檢查不證明官方拓撲正確。
- **升降停止誤認**：不再用左右輪平均速度判定停止，避免一正一反旋轉抵消；新完整路線執行器也不會因控制器進入Waiting就直接終止世界時間。舊`physics_sim.py`的短情境`reached/false_marker`仍是診斷結果，不作完整賽道驗收。
- **驗收證據不足**：新增缺欄位、非單調時間、無輪速卻位移、垂直瞬移／不合理俯仰、偽造ADC、取樣時間及雜湊不符等拒絕情境。

## 實際試驗

對照組是`add30a7`；修正組是目前原生來源。另有**未採用的實驗組**：收線PWM100→150、升降等待23.35→29秒、總期限180→360秒，只在輸出資料夾複製的程式中編譯，沒有修改主設定。各組事前固定相同五個種子2026110701～2026110705，全部失敗紀錄保留。

比較採明示的高扭力假設`max_accel_mps2=6`，其餘輪差／電量／抓地有固定種子擾動。這不是實車校正：原假設2.5m/s²不足以通過目前推定的部分坡道／蹺蹺板；單改控制程式不能使不具物理可行性的車型通過。開發批次也重現過感測器在突變坡面前落到路面以下的模型接縫，已以明示的前輔助輪支撐／俯仰假設修正，不能把先前失敗全歸咎於馬達。

| 組別 | 完成／5 | 最遠經過的推定路線門 | 終止結果 |
|---|---:|---:|---|
| add30a7對照 | 0／5 | 75／209 | 3控制器故障、1機構外停滯、1車輪出界 |
| 掉線計時修正後 | 0／5 | 75／209 | 同上，逐案結果相同 |
| 收線150／升降29秒實驗 | 0／5 | 75／209 | 1控制器故障、2機構外停滯、2車輪出界 |

路線門數不是官方距離成績，也不是成功率。三組均未到達真正的模型升降台或蹺蹺板，因此機構通過檢查不能標為成功；機構本身只有獨立物理回歸測試。提高收線PWM沒有帶來完賽改善，故不替換主設定。

目前可見的失敗包括推定坡道上的長時間單側收線無法完成，及未核實F交會附近的寬白被當成升降標記。其中一次誤判前是**五顆都低ADC**，所以單加「必須五白」也無法唯一辨識升降台；同時該交會的真實層次仍未知。這是標記觀測與拓撲假設的共同風險，不能宣稱已證明實車同一處必然會失敗。

三組共15份軌跡已核對雜湊、實際核心重播與物理感測來源；詳細雜湊／結果見`docs/simulations/2026-11-03-squad-course.json`。開發期間的舊模型批次留在build-output供追查，不與最後比較組拼湊成功。官方前置檢查仍拒絕核實不足的模型，官方驗收執行0次／通過0次，五連跑目標未達成。

## 操作與驗證

```powershell
py -3.11 -m pip install -r simulation/requirements.txt
py -3.11 tools/run_course.py --output build-output/full-course/new-run --plant-json simulation/plant_high_torque_hypothesis.json
py -3.11 tools/audit_course_run.py build-output/full-course/new-run
py -3.11 -m unittest discover -s tests -v
```

每次使用新的輸出資料夾；使用`--baseline add30a7`建立對照，`--experiment capture150_lift29`建立單獨的未採用實驗。`--replay-only`會使用批次凍結的賽道，避免混用後來修改的路線。歷史批次使用較新裁判時加`--current-referee --audit-label <新名稱>`，舊裁判快照不覆寫。

57項Python測試、原生C++斷言及Nano Old Bootloader編譯通過；預設Flash8776 bytes／全域RAM203 bytes。這是靜態建置用量，不是執行期峰值或實車性能。Chrome無介面測試確認5組選擇、播放前進、拖曳與圖面切換無頁面錯誤，並視讀截圖。未燒錄、未操作車子、未更動穩定版或根目錄XML／INO。

## 尚需完成

官方完整驗收仍需核實方向／指定出口、遮蔽交會、賽道及機構尺寸／配置與F用途，以及量測輪距、感測器位置、車輪PWM－速度／負載與齒輪箱保持力。目前模型已能實際執行這些假設並保留失敗，不再只有檢查表；但還不能用未證實的假設宣告五次官方完賽。後續應先以實際幾何與馬達資料校正並解決機構／標記辨識，再凍結相同條件進行新五次批次。
