# 第四號彎推頭、全黑直衝：控制分支修正

> **後續第一彎回報**：最新彎道基準100、內輪8／50；中央線200 ms後從100每20 ms加5，最高230。此文其餘明確F值及失線限制保留，[現行升速參數](FIRST_CORNER_2026-10-25.zh-TW.md)覆蓋下方80 ms／125／10等前版數字。

使用者回報第四號彎推頭，之後無視黑色直線暴衝。沒有當次原始ADC、F值或狀態紀錄，不能斷言唯一原因。本次修正以下由程式本身可確認的輸出路徑，並撤回1 ms確認設定；未宣稱實車問題已解決。

## 已確認的程式缺口

1. 原正常F=10分支不寫馬達，會保留前一圈命令；若前一圈是直道，就可能保留230。
2. 原F編碼採`<70`，轉向判斷卻另外採`<70`與`>70`。例如A4在線、A2剛好等於70時，F雖為8或12，左右轉條件仍可能都不成立，掉入預設230直行。這是程式可達路徑，不是已觀察到本次ADC恰等於70。
3. 1 ms回線確認可能更快接受短暫線片段，且原正常分支沒有要求中央線穩定才恢復230。它不是已量測的1 ms取樣率。

## 現行動作

| 情況 | 現行輸出／處理 |
|---|---|
| F=4中央窄線 | 先125；必須保持中央80 ms，才每10 ms增加10 PWM，最多230 |
| 離開中央或進入搜尋／升降等其他狀態 | 清除直道穩定與加速記憶；不可把先前230帶到下一次中央讀值 |
| F=8／12 | 左內輪25／75、右外輪125；依F值，不再另用嚴格`>70`判斷 |
| F=2／6 | 左外輪125、右內輪25／75 |
| F=10或未分類的正常循跡圖樣 | 兩輪PWM=0、故障鎖定；不再延續前一圈速度 |
| F=0且有未過期的確認方向 | 既有有界樞紐搜尋，外輪125／反轉內輪95，最多800 ms |
| F=0且沒有方向證據 | 兩輪45，單次最多120 ms，超時鎖定停止；不會由此狀態要求230 |
| 缺口中側線回來 | 20／45或30／45前進差速，左右鏡像；連續窄線15 ms才退出 |
| F=14 | 既有升降台或寬白／終點狀態優先；寬白前進45，不走預設230 |

所有方向確認、尖角回線確認、缺口回線確認均由1 ms恢復為15 ms。遇到不符合的觀測就重新確認，事件總期限仍固定，不能因短片段而無限延長。

直道升速第一次在中央持續至少80 ms後增加10，再以不小於10 ms的間隔逐步增加；不是每圈增加，也不因一次迴圈延遲補跳多步。直道上限仍保留使用者指定230，但不再是一看到中央線就直接下230。

升降台23.35秒、第一個寬白標記假設、離台45與原終點條件保留。本次沒有調整ADC門檻70或感測器極性，也沒有聲稱三感測器能辨別所有黑底、白字或其他干擾。

## 未排除的原因與狀態

若實際黑底被ADC閾值錯判成F=4，純F值控制仍無法知道車已在黑底；沒有該次原始資料，不能排除此情況。PWM0也只是移除驅動，不代表主動煞車或立即消除高速慣性。

縮短缺口期限可能使原本可通過的長虛線停住；對F=10立即故障也比舊版嚴格。這些是本次明確採用的行為取捨，不代表已驗證全圈表現。

本次僅同步產生XML／Arduino並檢視產物差異，依先前指示未執行額外測試、編譯或燒錄。更動位於開發分支，既有v0.4.0 Release不包含。
