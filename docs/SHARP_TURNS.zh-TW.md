# 60°／90° 尖角轉彎策略

主檔為根目錄 `car.xml`；`car.ino` 由這份 XML 使用原廠 CAGEBOT 產生器同步匯出。仍只使用 A4/A3/A2 控制，A5/A1 僅記錄。

## 如何轉彎

1. 一般循跡維持原比例轉向。F=8／12 記住左側方向；F=2／6 記住右側方向及當下毫秒時間。F=4連續80 ms才清除方向，短暫回中不清除，也不刷新方向時間；F=14立即清除方向。
2. 接著出現 F=0，且偏側紀錄在最近 250 ms 內，立即進入向該側的樞紐轉向，不等待原失線 41 圈停車。
3. 左轉：左輪反轉 PWM95、右輪前進 PWM100。右轉：左輪前進 PWM100、右輪反轉 PWM95。
4. 轉向至少 30 ms 後，連續 3 圈取得只有中央 A3 在線的 F=4，結束轉向、清除方向紀錄並恢復循跡。其他圖樣會清零確認圈數，但不重設轉向期限。
5. 從轉向開始滿 800 ms 尚未完成，兩輪 PWM=0 並鎖定；重新出現線也不會自動啟動，需重設／重新上電，並按原有啟動鈕開始。

60° 與 90° 使用同一套「轉到重新抓回線」策略，不以固定延遲假裝精確轉過某個角度。沒有編碼器或姿態回授，程式不會量到實際角度，也無法自動保證辨識兩者。

## 設定值

| setup 參數 | 值 | 意義 |
|---|---:|---|
| TURN_OUTER_PWM | 100 | 樞紐轉向外輪前進命令 |
| TURN_INNER_PWM | 95 | 樞紐轉向內輪反轉命令 |
| TURN_MEMORY_MS | 250 | 允許採用的偏側紀錄最長年齡 |
| TURN_CENTER_CLEAR_MS | 80 | 連續中央線多久後清除方向，避免單幀回中抹掉彎道證據 |
| TURN_MIN_MS | 30 | 開始接受中央線確認前的最短時間 |
| TURN_CONFIRM_COUNT | 3 | 連續中央線確認圈數，不是固定毫秒長度 |
| TURN_TIMEOUT_MS | 800 | 單次樞紐轉向總期限，逾時優先停車 |

這些是策略設定值，沒有實車角度／轉向時間量測佐證。本次未執行測試、編譯或燒錄；匯出 Arduino 是產生檔案，不代表實車已通過。

## 與原表的關係

- 正常循跡時，原 [三感測器對照表](SENSOR_TRUTH_TABLE.zh-TW.md) 仍適用；F=0 增加上述近期偏側轉向條件。
- 沒有近期方向證據的 F=0，兩輪 PWM70 直行跨短缺口，總期限250 ms；不再使用舊41圈計數作主要失線處理。完整起終點與缺口規則見 [測試賽道策略](ONE_LAP.zh-TW.md)。
- 樞紐轉向期間，當下 F 不直接決定左右馬達；沿用進入時的方向，直到確認中央線或逾時。
- 短缺口前的普通左右修正也可能觸發本策略；它不能只靠三顆感測器保證區分虛線缺口、白字、一般失線與真正尖角。
- 如果尖角沒有先形成偏側觀測，程式不能據此選對方向；這不是含路段順序的 T 字岔路策略。
- 啟動按鈕仍僅在開機等待，運行中沒有新增按鈕停止功能。鎖定停止時主迴圈設定 LED 藍色；PWM=0 不代表主動煞車。

來源修改在 `tools/rewrite_car.py`，再同步產生 XML 並用 `tools/export_car.mjs` 或 CAGEBOT 匯出 Arduino。原始舊版仍保存在 `legacy/`，不覆寫。
