# v0.3.2-rc.1 交叉與彎道測試版

燒錄 **`firmware/field_crossing/field_crossing.xml`**，已帶入目前的實測校正並啟用按鈕啟動。
仍從窄白線開始，先架空確認方向與停止按鈕，再拔掉 USB、用電池供電落地測試。
中央 A3 對準窄白線，釋放再按按鈕開始，運行中再按一次停止；每次最多 60 秒。
本版自動起終點維持關閉，不從大片全白區啟動。

## 調整原因

前一版現場紀錄兩次從循跡進入三顆全白（mask=14），以 PWM 35 前進，
約 350 ms 後觸發不確定超時停車。使用者確認直線可跑、馬達會轉。
這份紀錄可以確認保護停車條件，不能據此量出實際路口寬度、車速或需要多久才能離開。

## 這版改動

- 全白通過使用獨立 `wide_pwm=50`；其他一般不確定狀態仍使用 PWM 35。
- 全白事件最長 `wide_timeout_ms=900`，找回可信窄線後恢復循跡。
  900 ms 是有界測試值，尚未實測證明足夠，不能視為已解決所有路口。
- 尋線偏移門檻改為 `search_edge=400`。兩顆相鄰在線的可信偏移約 ±500，
  原本 600 門檻可能不會進入側向尋線。
- 可信偏移超過門檻時保存方向與裝置時間；進入全白事件時只採用最近 250 ms 內的方向。
  中央線短暫出現不會立刻抹掉這份近期方向，但超過 250 ms 的舊方向不能採用。
- 全白期間先直行；若轉為全黑，有上述方向證據才向該側尋線，內輪停止、外輪 PWM 50。
  無方向證據則短暫降速直行，不猜左右。它仍受進入全白事件時固定的 900 ms 總期限約束。
- 分類變化、全白轉全黑、短暫白線都不重設總期限。只有連續確認可信線才退出本次不確定事件。
- 直線基準 PWM 60、彎道基準 45、輸出上限 70；校正與 A4/A3/A2 控制範圍維持不變。
  A5/A1 只記錄，沒有新增反轉馬達或自動重啟。

預設未校正 `practice_controller` 與舊 `field_low_speed` 的方向記憶功能預設停用，
只有新 `field_crossing` 設定啟用本次行為。既有檔案已從相同來源重新產生。

## 現場測試

1. 燒錄成功後，在短直線上啟動，先確認仍可直走與手動停止。
2. 單獨測一次交叉處。記錄是否通過、是否在 900 ms 期限附近停下，以及有沒有走錯支線。
3. 單獨測左彎與右彎，錄下失線前、全白／全黑期間和車輪轉動。
4. 資料標籤使用 TRACK；電腦採集結束不會停止車子。
   藍牙不穩定時以錄影與分段人工觀察記錄，USB 僅用於架空測試，不拖線跑車。

近期偏向也可能只是正常左右修正；若路口後有全黑缺口，可能被當成彎道而轉錯。
三顆相同讀值無法保證區分文字、交叉、銳角與終點。若發生錯轉或逾時，
保留紀錄與錄影，下一步要補路段上下文或量測，而不是取消超時保護。
PWM=0 不是主動煞車，車子滑行距離仍需實測。

## 驗證

原生回歸涵蓋超過舊期限的全白通過、左右鏡像轉彎、方向過期、全白轉全黑、
共用期限、短片段不重設計時及手動停止。原廠 CAGEBOT 匯入／輸出、儲存回讀、
原生執行一致性與 Nano 編譯均有驗證，詳見 `field_crossing.verification.json`。
尚未上車驗證這次改動，尚無交叉／彎道通過率或整圈成功證據。
