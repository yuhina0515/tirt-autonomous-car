# 升降機構：十字停車、等待與離台

依 [官方規則整理](TIRT_RULES_2026.zh-TW.md) 所列第6頁要求：停在升降台十字白線，下降完全停止前不可離開或碰撞機構。原文提供27秒、容差±5%，但沒有提供車輛可直接讀取的「下降完成」訊號。

## 目前預設與假設

使用者回覆「途中似乎不會遇到其他十字」，因此本版暫設**離開起點、確認窄線後遇到的第一個持續寬白標記，就是升降台**。

這是路線假設，不是三顆感測器能識別升降台。F=14只代表中間三顆同時在線，普通路口、寬白區或部分彎道也可能出現相同圖樣；若第一個標記不是升降台，就會在錯誤位置停等。不能由這個計數推知官方地圖的實際路段位置。

## 控制流程

| 狀態 | 程式行為 |
|---|---|
| 等待升降台 | 窄線連續100 ms確認起跑後，F=14連續30 ms算一個寬白標記；目前選第1個 |
| 台上停等 | 停車命令兩輪PWM=0，不增加向前對位動作；從這次停車命令開始計時28.35秒 |
| 離台 | 等待滿後，兩輪向前PWM45；連續100 ms取得窄線後，恢復原循跡 |
| 已通過 | 升降台功能本圈不再觸發；之後的寬白標記交回一般寬線／終點處理 |
| 離台失敗 | 離台起算1500 ms尚未取得連續窄線，鎖定停車，需重設／重新上電 |

等待及離台時，尖角、缺口及終點辨識不會搶走馬達命令。等待時間不因感測器圖樣改變而重設；同一寬白事件也不會每圈重複計數。要連續100 ms窄線才解除該事件的標記鎖定。

升降台啟用時，終點停車必須等升降台離台狀態完成後才開放；不會把升降台本身的長時間全亮判成終點，也不會被原900 ms寬線期限中斷。整次運行180秒上限與既有故障／終點鎖定仍然優先，升降等待包含在總時間內。

## setup 參數

| 參數 | 預設值 | 意義 |
|---|---:|---|
| LIFT_ENABLED | 1 | 啟用升降台流程；回到沒有升降台的練習墊時改為0 |
| LIFT_CROSSING_INDEX | 1 | 起跑窄線確認後，第幾個確認的寬白事件是升降台；不是地圖段號 |
| LIFT_MARKER_CONFIRM_MS | 30 | F=14持續確認時間 |
| LIFT_CLEAR_CONFIRM_MS | 100 | 窄線確認／解除事件鎖定時間 |
| LIFT_WAIT_MS | 28350 | 停車命令後的等待時間，單位毫秒 |
| LIFT_AUTO_EXIT | 1 | 等待滿後自動離台；改為0會保持停車，不會因等滿而離台 |
| LIFT_EXIT_PWM | 45 | 離台前進命令 |
| LIFT_EXIT_TIMEOUT_MS | 1500 | 單次離台最大時間，包含抓線確認 |

## 尚未確認的物理條件

**28.35秒只是27秒加5%的規則上限換算，不是現場量得的完全停止時間。** 現有車輛沒有機構停止回授；因此到時間就自動離台，仍不能保證符合「下降完全停止後才離開」。若實際下降未停止，不能只依本參數宣稱可離台。等待也從PWM停車命令開始，不代表車體那一刻已停止滑動。

本版沒有假設感測器到輪軸的幾何距離，也沒有猜一段對位前進時間。停車命令發出的位置能否把車停在合法位置、等待期間會不會滑動、PWM45能否順利離台，都尚未確認。PWM=0是移除驅動，不是主動煞車。

舊練習墊照片與正式升降台路線不能混用：如果沒有升降台而維持啟用，第一次寬白事件仍會被當成升降台停等。官方27秒等待與一般途中停止10秒計分條文的適用區別，仍依裁判解釋。
