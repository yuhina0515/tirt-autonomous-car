# v0.2.0-rc.1 現場操作說明

這是尚未上車驗證的預發行版，針對「全白起點出發、銳角尋線、回到全白區停止」準備。
GitHub Release 的 `tirt-v0.2.0-rc.1.zip` 包含來源、可編輯 XML、同源 Arduino、採集工具與本說明。
附檔 SHA256SUMS.txt 可用 PowerShell `Get-FileHash` 比對下載檔。

## 選哪個檔案

| 檔案 | 用途 |
|---|---|
| `firmware/stationary_capture/stationary_capture.xml` | 先燒錄，馬達始終關閉，採集校正資料 |
| `firmware/practice_controller/practice_controller.xml` | 新跑圖控制器，預設 `configReady=0`，不會啟動 |
| 同資料夾 `.ino` / `manifest.json` | 同源 Arduino 與雜湊；Arduino IDE 選 Nano / ATmega328P (Old Bootloader) |
| `legacy/` | 舊來源備份，無法據此確認目前車上版本 |

請按 [現場測試單](FIELD_TEST.zh-TW.md) 採集白線與黑底，產生實測校正設定，再啟用與重新產生跑圖 XML。
沒有 Python 時，可在 CAGEBOT setup 中依實測修改 `line0..4` / `background0..4`（A5→A1），
確認後才把 `configReady` 改為 1，保存為另一個有版本名稱的 XML。不要只改旗標而保留假定端點。
先將輪子架空，確認左線使左輪較慢、右線使右輪較慢，按鈕能停止，再落地測試。

## 控制流程與暫定值

| 情境 | 行為與參數 |
|---|---|
| 全白起點按鈕啟動 | `departure_pwm=45` 直行，2 秒取得不到可信線即停止；起點不當終點 |
| 確認離開起點 | 可信白線連續 `departure_confirm_ms=300`，鎖存離開標記 |
| 90°／60°等銳角失線 | 最後可信偏移絕對值至少 `search_edge=600` 時向該側尋線；內輪停止、外輪 `search_pwm=65`，最長 `search_timeout_ms=650` |
| 直線全黑缺口 | 最後偏移不達邊緣門檻時，PWM 45 直行，最長 `gap_timeout_ms=200` |
| 分裂、跳變、低對比 | 保留先前曲率並降速，最長 `uncertain_stop_ms=120` |
| 三顆全白 | 低速直行，最長 `wide_timeout_ms=350`；起終點外的路口仍須實測 |
| 終點候選 | 已離開起點、從啟動經過 `min_lap_ms=15000`、同一次寬白事件連續全白 `finish_confirm_ms=250`，輸出 PWM=0 並鎖定 |
| 整次執行 | `max_run_ms=180000` 上限；按鈕停止、排程超時、失線超時均優先停止 |

尋線方向與期限在不確定事件開始時固定。未連續找回可信線前，分類變化與短暫看到線不能重設總期限。
內輪 PWM=0 是停止驅動，並不是主動煞車；本版沒有反轉馬達。所有 PWM 不超過 100。
A4/A3/A2 參與控制，A5/A1 僅記錄。左右方向錯誤時先檢查接線與實際輪向。

## 必須實測的地方

1. 先將 `lap_enabled=false` 測試循跡、左／右銳角及虛線。此設定不允許從全白區盲走，請放在窄白線啟動。
2. 每個角落重複測試，記錄「邊緣出線→全黑→重新取得白線」時間。
   若未形成可信偏邊就直接全黑，本版會使用短缺口模式，可能仍無法轉過；需要調整進彎速度、感測器位置或另加路線資訊。
3. 推車或低速量中央交叉線、文字、虛線缺口、起終點全白區的感測器覆蓋時間。
4. 啟用 `lap_enabled=true` 後，先單獨驗證出發與終點，再整圈測試。
   `min_lap_ms` 應依實測最快圈程留餘量；`finish_confirm_ms` 須能區分途中寬白區與終點，且小於 `wide_timeout_ms`。
5. 若途中寬白區與終點的觀測／持續時間重疊，這套時間條件無法區分。
   請停用自動終點判斷，增加已驗證的路線進度、編碼器或其他辨識方式；不要只拉長失線時間。

本版沒有地圖定位、里程計或路段順序判斷，尚不能證明跑滿一圈。
出發方向由實際車頭朝向決定；照片不足以確認合法路線方向與各段行進時間。
白字可能造成誤轉或誤停；物理停車距離、銳角通過能力與全圈成功率尚未量測。
測試時保留車上按鈕與電源開關可及；電腦停止收資料不會停止車子。
